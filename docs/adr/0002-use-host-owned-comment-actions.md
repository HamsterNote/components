# 评论数据采用宿主持有的分动作契约

Pro 的通用 `CommentDrawer` 不依赖 Card 类型或 `@hamster-note/cards`。它接收宿主提供的评论数据，并通过可异步的新增、回复、编辑和删除回调分别提交用户动作；组件只管理输入、展开和提交状态，不生成业务 ID、不直接请求固定后端，也不把整棵评论树作为一次变更回传。评论以带 `parentId` 的扁平数组输入，组件负责组装并无限递归展示真实父子关系；评论标识符统一使用 `string`，`parentId` 为 `string | null`，动作回调与分页层级键沿用同一类型。`createdAt` 与可选的 `updatedAt` 统一使用 ISO 8601 字符串；组件只将 `createdAt` 作为同级倒序排序依据，不内置时区、相对时间或固定展示格式。时间区域必须由宿主通过 `renderTimestamp(comment)` 完整渲染，宿主自行解释创建时间、编辑状态、语言和时区，组件只保留其布局位置。每组同级评论均按 `createdAt` 倒序排列，不依赖输入数组顺序。回复线程默认折叠并由用户逐层展开，折叠入口不显示回复数量，只有展开层级才渲染回复列表及其加载哨兵。根评论与每条评论的直接回复分别拥有独立的 `hasMore`、`loading` 和 `error` 状态，使无限递归树的每个层级都可按需加载；首次展开尚未载入直接回复且 `hasMore = true` 的线程时，组件立即调用 `onLoadMore(comment.id)` 请求第一页，并在原位呈现加载、失败和重试状态；后续页仍由列表末尾哨兵触发。Drawer 打开时，如果根层尚无已加载评论且其状态为 `hasMore = true`、`loading = false`，组件立即调用 `onLoadMore(null)` 请求根评论第一页；失败不关闭 Drawer，而是在空列表位置提供错误与重试状态，后续根评论页再由末尾哨兵触发。当根列表或某个已展开回复列表的末尾进入可视区域时，组件通过 `onLoadMore(parentId)` 自动表达对应层级需要更多数据，根层级使用 `parentId = null`。分页游标、页码、请求参数、去重和结果合并均由宿主管理，评论模型不提供回复总数字段。新增回复、编辑和删除均通过 ID 定位。异步新增、回复或编辑回调成功后，组件立即清空相应草稿并退出当前输入状态，不等待受控评论数组刷新；回调失败时则保留草稿和输入状态以便重试。动作失败时，组件在操作位置显示安全的通用文案，并允许宿主根据动作类型和错误对象转换为可信的用户文案；组件不直接显示任意异常消息。删除一条评论表示级联删除以它为根的整棵回复子树，组件在确认提示中明确这一影响范围，实际持久化仍由宿主完成。评论正文是保留换行的纯文本字符串，组件不解析 HTML；宿主可以覆盖只读正文渲染，但新增与编辑仍提交字符串。新增能力由宿主按评论上下文提供，回复、编辑和删除能力由宿主逐条评论提供，组件不根据作者身份推断权限。评论作者区域由宿主通过 render prop 完整渲染，组件不定义或查询作者模型；评论数据类型允许宿主附带供渲染使用的扩展字段。这样 Card、笔记、任务或文档等宿主都能按动作接入自身的持久化、权限校验与失败处理，而评论组件仍可跨业务复用。

动作能力的具体 API 为：宿主通过 `canCreate: boolean` 声明当前评论上下文是否允许新增根评论，并通过 `getCommentCapabilities(comment)` 一次返回该评论的 `canReply`、`canEdit` 和 `canDelete`。这些能力是当前查看者在当前上下文中的权限投影，不属于评论领域数据；组件不缓存能力结果，也不根据动作回调是否存在或作者身份推断权限。

`onCreate`、`onReply`、`onEdit` 和 `onDelete` 四个动作回调均为必填。回调是否存在只表示宿主已经接入对应功能，动作入口是否可见和可用则只由 `canCreate` 或逐条动作能力决定；组件不会将回调存在性作为权限信号。

四个动作回调均使用具名对象载荷：`onCreate({ content })`、`onReply({ parentId, content })`、`onEdit({ commentId, content })`、`onDelete({ commentId })`。组件只提交动作所需字段，不构造新的评论实体，也不把当前评论对象当作待持久化快照传回宿主。

异步动作采用按目标局部锁定，而不锁定整个 Drawer。新增根评论提交期间只禁用根评论输入区；回复或编辑提交期间只禁用对应输入区；删除提交期间禁用目标评论及其整棵已渲染回复子树的动作入口，避免对子树继续回复、编辑或重复删除。同一动作目标不能重复提交，其他不相关评论仍可正常操作。组件因此按动作及目标分别维护提交状态，不使用单一的全局 `isSubmitting` 状态。

组件允许不同评论的回复或编辑输入区同时打开，各输入区独立保留草稿、提交状态和错误状态；根评论输入区也始终作为独立输入区存在。同一条评论同一时刻只显示回复或编辑中的一种输入模式，用户切换模式时保留暂时隐藏的另一模式草稿。折叠回复线程不会丢弃其中尚未提交的草稿，再次展开后恢复；关闭 Drawer 则清空全部组件内部草稿和输入模式，避免下次打开时带入已经脱离当前交互会话的内容。一个输入区提交中不妨碍用户打开或操作其他评论的输入区。

存在新增、回复、编辑或删除请求时，用户仍可通过关闭按钮、遮罩或 `Esc` 立即关闭 Drawer。关闭只结束当前界面会话：组件不阻止关闭、不取消已经调用的宿主回调，也不假设其返回的 Promise 支持取消；宿主负责决定请求是否继续、取消或回滚。关闭后组件清空草稿、输入模式、提交状态和错误状态；随后完成的请求不会重新打开 Drawer，也不会向已关闭界面呈现结果。下次打开时，组件完全以宿主传入的最新评论数据和分页状态为准。

进入编辑模式时，组件以当时的 `comment.content` 初始化草稿并记录编辑基线。编辑期间宿主传入的同一评论正文发生变化时，组件不会用新正文静默覆盖本地草稿，而是在输入区显示可访问的外部更新提示。用户可以继续保留当前草稿，也可以显式选择使用宿主传入的最新正文；选择后，最新正文同时成为新的草稿与编辑基线。组件不自动合并内容、不判断版本先后，也不改变 `onEdit({ commentId, content })` 的动作载荷；真正的并发校验由宿主负责，提交被拒绝时仍保留草稿并按既定规则显示错误。

宿主传入的受控 `comments` 是评论是否存在的唯一事实来源。某个评论 ID 不再出现时，组件立即停止渲染该评论，并清理该评论及其已知后代关联的回复与编辑草稿、输入模式、展开状态、提交状态、动作错误和编辑冲突状态，不保留“评论已删除”占位符。已经调用的宿主动作仍不由组件取消，完成后也不会恢复已移除的界面；若宿主之后重新传入同一 ID，组件将其作为当前数据中的评论重新渲染，但不恢复此前的本地状态。

组件只承担与具体业务无关的非空校验：新增、回复和编辑提交前使用 `content.trim()` 判断正文是否仅由空白组成，纯空白内容不可提交，并在对应输入区显示可访问的通用提示。校验只用于判断能否提交，组件不会裁剪或改写正文；通过校验后，动作回调收到用户输入的原始字符串，包括首尾空白、换行和缩进。组件不内置最大长度，也不处理敏感词等业务规则；长度及其他领域校验由宿主在动作回调中执行，失败后沿用既定的错误文案转换与就地呈现机制。

组件为全部用户可见文本提供默认中文文案，并允许宿主通过统一的 `messages` 属性按项覆盖。可覆盖范围包括标题、输入占位符、提交与取消、回复、编辑、删除、查看回复、加载、重试、空状态、通用动作失败、纯空白校验、级联删除确认、外部正文更新冲突、“使用最新内容”以及交互控件的无障碍标签。宿主不必提供完整文案对象，未覆盖项继续使用组件默认值；需要结合当前评论等运行时上下文生成的文案使用函数形式。组件不绑定或要求任何特定国际化库，宿主可自行将其国际化系统的翻译结果投影到 `messages`。

`CommentDrawer` 的打开状态完全由宿主通过 `open: boolean` 与 `onClose(): void` 控制。Pro 组件只直接暴露评论场景需要的 `placement`、`size`、`closeOnBackdrop`、`closeOnEsc`、`showCloseButton` 和 `showFullscreenButton` 等有限 Drawer 配置，标题由 `messages.title` 管理；不提供 `drawerProps` 或任意底层属性透传。`closeOnBackdrop` 直接沿用基础 Drawer 的属性名称，不另设语义相同的 `maskClosable` 别名，且默认值为 `true`。未传入的配置采用 `CommentDrawer` 自身稳定的默认值，使 Pro 的公开契约不随基础 Drawer 的全部属性和内部演进同步扩张。

全屏配置只表达入口是否可见，不虚构基础 Drawer 尚不具备的“禁止全屏”能力。`CommentDrawer` 提供 `showFullscreenButton?: boolean` 并默认显示按钮，使进入全屏与退出全屏两个方向的动作清晰、可发现且支持键盘操作；宿主可以隐藏按钮，但标题拖动仍可在自适应状态与全屏状态间切换。组件不提供名为 `fullscreenable` 的属性，以免将隐藏按钮误解为禁用全屏切换。

`CommentDrawer` 默认从右侧展开（`placement = 'right'`），自适应状态的默认宽度为 `420px`；宿主可以通过 `placement` 与 `size` 覆盖。窄视口下的实际宽度不得超过可用视口宽度，不能造成横向溢出，但组件不会仅因视口变窄就自动进入全屏状态；全屏状态仍由用户通过清晰的全屏切换动作进入。宿主将方位改为 `top` 或 `bottom` 时，`size` 按基础 Drawer 的既有语义表示高度。

`showCloseButton` 默认值为 `true`。即使遮罩和 `Esc` 默认也可关闭，标题栏仍提供清晰、可发现且适合触屏使用的关闭入口；当宿主关闭遮罩关闭或 `Esc` 关闭时，该按钮也作为可靠退出路径。只有宿主已经提供明确且等价的关闭入口时，才应显式隐藏该按钮。

删除动作始终经过组件内置且不可关闭的二次确认。用户首次点击删除时，组件在当前评论附近呈现非阻塞式确认界面，不使用 `Dialog`；确认文案明确说明目标评论及其全部回复将被级联删除。只有用户再次确认后，组件才调用 `onDelete({ commentId })`，取消确认不会调用动作回调。确认界面打开期间只锁定该目标评论的删除入口，不妨碍其他评论操作；宿主可以通过 `messages` 定制确认文案，但不能绕过确认步骤。真正的数据权限与服务端校验仍由宿主负责。
